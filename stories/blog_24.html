From Web Apps to Deterministic Agent Skills & Autonomous SOC 2 Type II Audit Studios: Engineering SkillForge AI and TrustForge SOC 2

In enterprise security, governance, risk, compliance (GRC), and data privacy, "close enough" is a failing grade. If an AI agent audits your cloud IAM policies or your AICPA SOC 2 Type II control samples three times and produces three slightly different numbers, no external CPA auditor or CISO will sign off on it. That insight drove my two newest open-source engineering releases: SkillForge AI and TrustForge SOC 2.

Two New Open-Source Agentic & Security/GRC Web Studios (#33–#34):
1. SkillForge AI — Web-App-to-Agent-Skill (SKILL.md), Deterministic Python CLI, and Model Context Protocol (mcp_server.py JSON-RPC 2.0) Compiler Studio with 6 industry security/GRC/privacy presets and 5-Gate verification (GitHub).
2. TrustForge SOC 2 — Autonomous AICPA SOC 2 Type I & Type II Readiness, 5-TSC Continuous Evidence Engine (28 Criteria), 7-Gate Exception Triage, Vendor CUEC Analyzer, and ISO 27001 / NIST 800-53 / HIPAA / GDPR / PCI-DSS Crosswalk Studio (GitHub).

1. SkillForge AI: Compiling Web Workflows into Verified SKILL.md & MCP Tools

Everyone is building AI agents, but turning an existing web application, OpenAPI 3.1 service, or security playbook into a reliable agent tool still requires glue code that is rarely tested for determinism. With SkillForge AI, I built a 4-stage compiler studio that takes a workflow specification and synthesizes the entire portable agent package automatically:

  • Stage 1 — Workflow & Schema Architect: Parses OpenAPI 3.1 specs, policy rules, or natural-language blueprints into strict JSON Schema Draft 2020-12 input/output contracts and compliance control mappings (CIS AWS, NSA/CISA Kubernetes, AICPA SOC 2, GDPR Art. 25/30/32, OWASP API Top 10, FinOps).
  • Stage 2 — Deterministic Engine Synthesizer: Generates a zero-dependency Python CLI engine (scripts/engine.py), an open-standard SKILL.md manifest (with YAML frontmatter and execution guardrails), and a dual stdio/HTTP Model Context Protocol server (mcp_server.py).
  • Stage 3 — 5-Gate Quality, AST Security & 3-Run Determinism Verifier: Before a skill can be exported, SkillForge AI parses the generated Python AST to guarantee zero dangerous calls or hardcoded secrets, validates the JSON Schema contract, runs the engine three consecutive times against the workload fixture to prove SHA-256(Run 1) == SHA-256(Run 2) == SHA-256(Run 3), and tests the live MCP JSON-RPC 2.0 handshake (initialize, tools/list, tools/call).
  • Stage 4 — Deterministic Multi-Artifact Packager: Bundles SKILL.md, mcp_server.py, scripts/engine.py, references/schema.json, and tests/test_skill.py into a byte-reproducible .zip archive.

2. TrustForge SOC 2: Autonomous Type II Auditing, 7-Gate Exception Triage & Privacy Crosswalks

Having led security, compliance, and privacy engineering initiatives across cloud and regulated enterprise environments, I wanted TrustForge SOC 2 to reflect how a real CPA firm and an internal Security/GRC engineering team actually execute a SOC 2 Type II engagement:

  • Full 5 Trust Services Categories (28 AICPA Criteria + 2022 Revised Points of Focus): Evaluates automated telemetry across Security (CC1.1–CC9.2), Availability (A1.1–A1.3), Processing Integrity (PI1.2–PI1.3), Confidentiality (C1.1–C1.2), and Privacy (P1.1–P6.1).
  • AICPA Audit Guide Sampling Mathematics: Switching between SOC 2 Type I (Point-in-Time Design) and SOC 2 Type II (3, 6, or 12-Month Operating Effectiveness) dynamically recalculates required audit sample populations—testing up to 661 discrete samples across daily monitoring, weekly infrastructure scans, quarterly access reviews, CI/CD pull requests, and HR termination revocations.
  • 7-Gate Adversarial Exception Triage (True Positive vs. Compensating Control False Positive): Raw scanner findings create audit panic when teams don't document compensating controls. TrustForge SOC 2 passes every flagged alert through 7 structured gates: verifying whether an asset is in the production boundary (Gate 0), checking network reachability (Gate 1), inspecting compensating controls like AWS Organization SCPs or GDPR Art. 12(3) statutory extensions (Gate 2), evaluating data sensitivity (Gate 3), checking remediation SLAs (Gate 4), and synthesizing a final CPA Section IV verdict (Gates 5–6).
  • Subservice Vendor SOC 2 CUEC & Bridge-Letter Analyzer (CC9.2): Audits upstream Carve-Out and Inclusive subservice organizations (AWS, Okta, Snowflake, Stripe, Auth0), calculates report period gap days to the audit end-date, flags missing Bridge Letters, and verifies that every Complementary User Entity Control (CUEC) is mapped to an effective internal control.
  • 6-Framework Crosswalk & 3-Run SHA-256 Determinism: Every criterion maps live to ISO/IEC 27001:2022, NIST SP 800-53 Rev. 5, HIPAA, GDPR, and PCI-DSS v4.0, and the entire Section III/IV audit pack is verified bit-for-bit identical across 3 runs.
