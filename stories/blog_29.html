Inside SkillForge AI v2: Replicating the Complete skill-creator Lifecycle & Multi-Skill Orchestration Across Ollama, Gemini, Claude & OpenAI

In the initial release of SkillForge AI (GitHub: Sockshare/skillforge-ai), I solved the problem of wrapping local web applications into live MCP JSON-RPC 2.0 tool servers. For v2, I wanted zero functional difference between how an expert engineer uses a meta-skill like skill-creator to build standalone CLI skills and multi-stage audit orchestrators—and what any general user can do visually inside SkillForge AI using either Local Ollama (any installed onboard model) or Google Gemini, Anthropic Claude, and OpenAI.

Core Principle: A production AI skill is not a static Markdown prompt—it is a self-contained software package (SKILL.md + pure headless Python CLI + JSON schemas + empirical paired benchmarks) refined through measurable A/B evaluations and held-out trigger optimization.

1. Two Ways to Build: Intent Interviews OR Python AST Web-App Decoupling

Real-world skill authoring starts from one of two places: a blank slate with a domain workflow in mind, or a working full-stack web application whose core domain math is trapped behind HTTP handlers and HTML templates. In skillforge/skill_creator_studio.py, SkillForge AI v2 handles both natively:

  • LLM Intent & Edge-Case Interview (interview_skill_intent): Uses your selected Ollama, Gemini, Claude, or OpenAI model to probe input formats, output contracts, false-positive edge cases, and non-trigger boundaries before generating a single line of code.
  • Headless CLI AST Decoupler (extract_pure_domain_python_from_webapp): Parses Python web apps via the standard library ast module, strips out HTTP/Flask/FastAPI server scaffolding, and emits a 100% standalone headless CLI skill (scripts/*.py) that executes deterministically on disk even when zero web servers are running.

2. Real Paired Subprocess Evals, HTML Review & 60/40 Trigger Optimization

Most "prompt builders" stop the moment a Markdown file is generated—leaving you blind to whether the skill actually outperforms a baseline prompt or hijacks unrelated user queries. SkillForge AI v2 implements the complete empirical loop on disk:

skill-creator Phase SkillForge AI v2 Module Artifact & Empirical Guarantee
Paired Subprocess Evals run_real_skill_creator_evals() Spawns isolated iteration-N/eval-M/{with_skill,without_skill}/outputs/ runs, grades assertions into grading.json, and aggregates pass-rate, latency, and token deltas in benchmark.json.
Human Feedback Rewriter submit_human_feedback_and_iterate() Captures per-test human critiques from the standalone HTML Eval Viewer into feedback.json, snapshots old_skill/, and rewrites SKILL.md using Ollama, Gemini, Claude, or OpenAI.
60/40 Trigger Optimizer optimize_trigger_description() Evaluates 20 realistic should-trigger and should-not-trigger prompts across a 60% train / 40% held-out test split to maximize recall and precision without overfitting.
Sequential Orchestrator orchestrator_builder.py Chains Phase 1 Discovery → Shared Handoff Directory → Phase 2 V&V & 7-Gate False-Positive Triage → Phase 3 Executive Report + Annexes, proving SHA-256(Run 1) == SHA-256(Run 2).

3. Multi-Provider Freedom + Zero-Copy Bridging into AiLabs

Every stage in SkillForge AI v2 shares a unified 4-provider model bar (llm_bridge.py). You can auto-discover local onboard models on http://127.0.0.1:11434 (such as qwen2.5-coder:7b or llama3.2:3b) for 100% air-gapped skill authoring, or switch to Google Gemini, Anthropic Claude, or OpenAI with a single dropdown. Better yet, every standalone skill or multi-skill orchestrator compiled into skills_workspace/ is automatically discovered via progressive disclosure inside AiLabs—closing the loop from visual skill engineering to live multi-agent execution.
