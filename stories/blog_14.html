Automating My Automations: From Manual CMMC Audits to Full-Stack Web Apps to LLM-Orchestrated Agent Skills

Most people try to build AI agents backwards: they start with a prompt before they understand the underlying problem, and hope the model figures out the edge cases. When I set out to engineer an end-to-end CMMC Level 1 (FAR 52.204-21 / NIST SP 800-171 Rev. 2) compliance assessment pipeline, I took a deliberate three-stage progression: first, I performed the entire audit by hand to master the ground truth; second, I built full-stack web applications to automate that manual work; and third, I packaged those web application engines into modular Agent Skills where an LLM acts as the autonomous orchestrator—automating my own automations.

The 3-Stage Engineering Progression:
Stage 1 (Manual Mastery): Execute the compliance review by hand to uncover every edge case in access boundaries, nested identity graphs, build provenance, and vulnerability SLAs.
Stage 2 (Web App Automation): Codify that domain logic into interactive FastAPI/Flask web workbenches inside Run Nexus.
Stage 3 (LLM-Orchestrated Agent Skills): Decouple the deterministic Python engines from the web UI into 6 standalone Agent Skills + 1 Master Orchestrator Skill capable of auditing any production application end-to-end from a single prompt.

Stage 1: Doing It by Hand to Learn Where Reality Breaks

You cannot automate a high-stakes security audit if you have never felt the pain of doing it manually. Before writing a single line of automation, I walked through the full CMMC Level 1 assessment lifecycle by hand across real production services—tracing configuration files, expanding deeply nested access groups, cross-referencing HR reporting chains, verifying build-provenance policies, and auditing vulnerability tickets against remediation SLAs.

Doing the work by hand exposed subtle real-world edge cases that naive scripts always miss:

  • Production vs. Non-Production Pollution: Repository searches naturally return staging, dev, test, and QA configurations alongside production files. Including non-production configs in a compliance boundary corrupts the entire audit scope.
  • Transitive Group Exclusions & Policy Denials: In enterprise identity graphs, a user might be excluded from one nested subgroup via a negative EXCLUDE rule while legitimately inheriting standing permanent access to the parent group through a sibling subgroup—or a paired automation/delegate account might be actively blocked by PII or zero-agent policy tags.
  • Dual Vulnerability SLA Clocks: A closed vulnerability ticket can be marked "within SLA" by an issue tracker's pause/reset rules while its raw creation-to-close calendar duration exceeds the nominal priority window (e.g., 30 days for P1 or 90 days for P2), requiring a three-bucket triage model (VALID, BREACHED, and VERIFY).

Stage 2: Building Full-Stack Web Applications to Automate the Manual Work

Once I knew the exact rules and edge cases, I built specialized full-stack web applications—integrated into my Run Nexus control plane—to replace hours of spreadsheet crunching and manual lookups with one-click visual workbenches:

  • UAR & Non-Person Entity (NoPE) Graph Workbench: A Breadth-First Search (BFS) identity graph engine that expands nested groups, verifies every human member against HR status and management reporting chains, separates findings into disjoint conditions, and evaluates machine-only lockdown tiers (L0–L6).
  • Vulnerability Verifier & Supply-Chain Provenance Suite: An interactive workbench where engineers input an application name and component IDs to audit vulnerability tickets against strict priority SLAs and verify Level 4 build/configuration provenance.

Building the web applications first was a crucial proving ground. A web dashboard gives you immediate visual feedback: you can inspect tables, verify chart distributions, test edge-case inputs interactively, and refine the data models until the output is rock-solid.

Stage 3: Automating My Automations — Turning Web Apps into LLM-Orchestrated Skills

A web application is fantastic when a human analyst sits down at a browser to audit one system. But what happens when you want to point that entire multi-domain compliance suite at any application across an enterprise, run all five verification domains sequentially, cross-verify their math, and produce a board-ready C-Suite audit package automatically?

Instead of stopping at the web UI, I extracted the battle-tested Python engines out of my web applications and architected a modular 6-Skill + 1-Orchestrator Agent Pipeline:

  1. Skill 1 — Production RPC & ACL Boundary Discovery: Scans production-only service bundles and security policies at repository HEAD, maps every RPC method by access classification (Read, Write/Mutate, Admin), and extracts the authoritative list of production hosting roles and caller groups.
  2. Skill 2 — Unified User Access Review (UAR) Auditor: Receives the exact group roster discovered by Skill 1 and audits all groups as a single unified estate—computing disjoint findings across Condition 1 (Standing Permanent Access), Condition 2 (Outside Target Reporting Chain), and Condition 3 (Former Employees), while generating asset-by-asset explanations for every principal or delegate agent actively marked Denied by policy controls.
  3. Skill 3 — Non-Person Entity (NoPE) & Role-Account Lockdown Checker: Audits the same discovered group roster for machine-only lockdown compliance (Level 0 through Level 6) and hard policy enforcement tags.
  4. Skill 4 — Level 4 Build & Configuration Provenance Verifier: Consumes the production scope and hosting roles discovered by Skill 1 to audit governing build/config policies and keystore configurations against Level 4 (submitted and authorized config) standards.
  5. Skill 5 — Vulnerability SLA Verifier: Audits security and vulnerability tickets across the application's issue-tracking components against strict priority remediation timelines.
  6. Skill 6 — C-Suite CMMC Level 1 Audit Reporter & Cryptographic Verifier: Synthesizes the outputs of Skills 1–5 into a concise executive audit report, five standalone evidence annexes, a 10-tab Excel workbook, and a cryptographically hashed canonical dataset.

Key Architectural Principles That Make Agent Skills Production-Grade

1. The LLM Orchestrates; Deterministic Code Calculates

The biggest mistake in enterprise AI is asking an LLM to perform set math over 150,000 identity records inside its context window. In my architecture, the LLM is the orchestrator and router—it resolves user intent, chains the six skills in sequence, passes verified file paths between stages, and synthesizes executive context—while deterministic Python engines execute the graph traversals, exclusion overrides, and SLA calculations with zero hallucination risk.

2. Cross-Domain Mathematical Reconciliation (100% UAR ↔ NoPE Correlation)

Because Skill 2 (UAR) and Skill 3 (NoPE Lockdown) evaluate the same discovered production groups from two different security perspectives, their numbers must reconcile mathematically. Specifically, any group with standing permanent human members (perm_humans > 0) must classify as NoPE Level 0, while any group with zero standing permanent humans (machine-only or 100% Just-in-Time / AoD-eligible) must classify at protected tiers Level 1–6.

By aligning how nested subgroup EXCLUDE rules are evaluated against root-group permanent entitlements and displaying total standing permanent humans alongside disjoint UAR conditions, the pipeline achieves a verified 100% group-for-group correlation between the UAR and NoPE engines.

3. Strict Binary PASS / FAIL CMMC Level 1 Reporting (Zero POA&M Allowed) & Standalone Annexes

Under 32 CFR § 170.21 and FAR 52.204-21, CMMC Level 1 is a strict binary Pass or Fail self-assessment—Plans of Action and Milestones (POA&Ms) are not permitted. If even one former employee retains active group access or a production policy sits below Level 4, the control is FAIL (NOT MET) and becomes a Mandatory Pre-Affirmation Remediation Blocker.

Furthermore, C-Suite executives do not want a 120-page raw CSV dump pasted into an audit opinion. I architected the Reporting Skill to produce a clean, 4–5 page C-Suite Executive Audit Report (.html, .docx, .md) containing the binary Pass/Fail scorecard, a dynamically rendered 5-Layer System Control Boundary Diagram, aggregated telemetry, and pre-affirmation blockers—while isolating all thousands of row-level evidence records into five standalone Supporting Evidence Annexes (Annex A–E) and a 10-tab Excel Evidence Workbook.

4. Two-Run Cryptographic Determinism (SHA-256 Attestation)

Finally, a compliance pipeline is only trustworthy if it is 100% repeatable. I built a Canonical Reviewed Dataset normalizer and a Two-Run Determinism Verifier that strips volatile execution timestamps, normalizes Office ZIP headers and chart metadata, and computes per-domain and master SHA-256 digests—proving cryptographically that two independent assessment runs over the same state produce identical results down to the byte.

The Takeaway: Build the Ladder from Manual to Autonomous

Going from manual execution → web application → LLM-orchestrated Agent Skills completely changes how you think about software engineering. Each layer compounds the one before it: manual work gives you uncompromising domain accuracy, the web app gives you a visual harness to perfect the engine, and turning that web app into composable Agent Skills lets you automate the automation itself.
